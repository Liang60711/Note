# 資源清單 Manifest 
K8S是`聲明式`的系統

Desired State（期望狀態） → Controller 持續調整 → Actual State（實際狀態）

所以需要編寫一份`期望清單`，交給 K8S讓他自動執行，直至符合期望狀態。

而這份期望清單的其中一種就是 `資源清單`。

<br/>

<br/>

## 目的
告訴 k8s，我要建立一個資源，並描述資源的配置。

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  namespace: default # pod 是依照 namespace 隔離
  labels:
    app: nginx # 用來讓 Service 資源綁定
spec: # 期望
  containers:
    - name: nginx
      image: nginx:latest
      ports:
        - containerPort: 80
status: # 狀態(由K8S自動維護)
  condotions:
  ...
```

## 查看資源下的 API 版本號

```
kubectl api-versions
```

若有看到 apps/vi 或 batch/v1，
但有一個特殊的直接叫 `v1`，其實是 `core/v1` 的簡寫。


## 查看 kind 和 apiVersion 之間的關聯
```
kubectl api-resources
```

## 查看資源規格
通常是查看欄位定義
```
kubectl explain pod
```
指定欄位
```
kubectl explain pod.spec.containers.name
```

## 查看資源 yaml (常用)

查看名為 nginx-pod 的 manifest 檔案
```
kubectl get pod nginx-pod -o yaml
```

## 查看資源物件的詳細描述

```
kubectl describe pod nginx-pod
```

## 創建資源

可以將manifest檔案，實例化成真實資源。

通常會在 Master node 下指令。

第一次可以使用 create，但如果資源存在，就會報錯

```
kubectl create -f pod.yaml
```

會嘗試讓資源符合新的 YAML，類似 updateOrCreate，童常會傾向用這個。
```
kubectl apply -f pod.yaml
```

創建後就會自動跑起來。


## 刪除資源

依照 manifest 檔案刪除資源：

```
kubectl delete -f pod.yaml
```

也可以指定資源類型與名稱刪除：

```
kubectl delete pod nginx-pod
```

刪除前可以先確認資源名稱，避免誤刪除：

```
kubectl get pods
```
